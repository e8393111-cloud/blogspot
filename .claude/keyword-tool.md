# 키워드 실측 도구 — 네이버 월간 검색량 + 경쟁도

주제를 감으로 고르다 20편을 묻었다(→ `.claude/keyword-log.md`). 이제 **숫자로 고른다.**
이 문서는 그 측정을 **매달 다시 돌리는 방법**이다.

---

## 무엇을 재나

| 값 | 출처 | 의미 |
|---|---|---|
| `pc` / `mobile` | 네이버 **검색광고 키워드도구**(Apps Script 프록시 경유) | 월간 검색량 |
| `total` | 네이버 **검색 OpenAPI** 블로그검색 | 블로그 문서 수 = 경쟁도 |
| `경쟁률` | `total ÷ (pc + mobile + 1)` | **낮을수록 좋다** — 수요 대비 공급이 적다 |
| `category` | 검색광고가 돌려준 `relKeyword` | 조회한 키워드와 실제로 매칭됐는지 검증용 |

**황금 구간 = 검색량은 있는데(월 1,000+) 경쟁률이 낮은 키워드.**

## ★반드시 지킬 4가지 (전부 실제로 겪은 함정)

**1. 검색광고 API는 공백이 든 키워드를 거부한다.**
`부산 여행` → `{"code":11001,"message":"hintKeywords 파라미터가 유효하지 않습니다."}`
→ 반드시 공백을 제거해 보낸다: ★Make의 `replace()`로 공백을 지우려 하지 말 것 — **동작하지 않았다.**
→ **공백 뺀 질의어를 미리 계산해 입력 배열에 `q` 필드로 함께 넣는다**(`{k:"부산 당일치기", q:"부산당일치기"}`).
(블로그검색 API는 공백을 그대로 둬도 된다. 오히려 붙이면 결과가 달라진다.)

**2. Apps Script는 `text/plain`으로 응답한다 → Make가 JSON으로 파싱하지 않는다.**
`parseResponse: true`로 두면 `data`가 문자열이라 `data.keywordList[0]`이 통째로 빈다.
→ HTTP는 `parseResponse: false`로 받고, **뒤에 `json:ParseJSON` 모듈을 하나 붙인다.**

**3. Make 매핑의 배열 인덱스는 1부터 시작한다 → 조회한 키워드는 `keywordList[1]`이다.**
`[0]`을 쓰면 **아무 값도 안 나온다**(빈 칸으로 저장돼 실패를 눈치채기 어렵다).
> 기존 시나리오 `🥇 황금키워드 자동분석 v2.1`(id 4375030)이 `[1]`을 쓰는 건 **정상**이다.

**4. 이터레이터 출력은 배열 원소의 타입에 따라 다르다.**
- 문자열 배열 → `{{2.value}}`
- **객체 배열 → `{{2.필드명}}`** (`{{2.value.필드명}}`이 아니다 — 빈 값이 나온다)
→ 이 도구는 `{k, q}` 객체 배열을 쓰므로 `{{2.k}}` · `{{2.q}}`.

## 다시 돌리는 법

1. **키워드 교체** — 시나리오 6031917의 모듈 1 `json` 파라미터에 있는 배열을 바꾼다
   (`mcp__Make__scenarios_get` → 블루프린트 수정 → `scenarios_update`)
2. **측정 실행** — `mcp__Make__scenarios_run` (scenarioId 6031917, responsive false)
   · 155개 기준 **약 6분 · 467 오퍼레이션**
   · `executions_get`으로 `eventType`이 `EXECUTION_END`가 될 때까지 확인
3. **집계 실행** — `scenarios_run` (scenarioId 6032112)
4. **결과 읽기** — `data-store-records_list`(dataStoreId 137130) → `measuredAt` 필드에 TSV 전체
   형식: `키워드 \t pc \t mobile \t total \t 매칭키워드`
5. **분석** — `scratchpad/analyze.py` 로 순위·황금구간 산출

### 오퍼레이션 예산
키워드 1개당 약 3회. Make Pro 월 10,000회이므로 **155개 측정 ≈ 470회(4.7%)**.
다른 시나리오(러닝 큐레이터·황금키워드 등)가 함께 도니 월 2~3회 측정이 안전선.

## 주의

- **자격증명은 기존 시나리오에서 재사용**한다. Apps Script URL과 네이버 API 키를 **저장소에 커밋하지 않는다.**
  필요하면 Make 블루프린트(4375030 또는 6031917)에서 읽어 쓴다.
- 검색광고 API는 검색량이 아주 적으면 `< 10`을 문자열로 준다 → 숫자 필드에 안 들어가고 비어 보인다. **빈 값 = 사실상 0에 가깝다**고 읽는다.
- 측정값은 **월간 검색량**이라 하루 이틀 차이로는 거의 안 변한다. 자주 돌릴 이유가 없다 — **월 1회면 충분하다.**

### 도구 변경 — 집계 출력을 146191로 돌렸다
집계 시나리오 6032112가 원래 결과 TSV를 **137130**에 쓰는데, 그 데이터스토어가
2026-09-08 철원 사진 조사의 `TQ_*` 레코드로 막혀 있어 `all` 레코드에 닿으려면 지우며 페이징해야 했다

　146191은 매 회차 비우고 쓰는 곳이라 `limit 1`로 바로 읽힌다. 되돌리려면 모듈 3의 datastore만 137130으로 고치면 된다.
