# 네이버 블로그 성장 에이전트 팀

**목표: 네이버 블로그 일 방문자 3,000명 이상 달성**
**독자: 30대 ~ 70대 이상, 핵심 타깃은 50~70대 시니어**

이 폴더의 서브에이전트들은 하나의 콘텐츠 제작팀처럼 협업하도록 설계되었습니다.
Claude Code에서 `해당 에이전트를 호출해줘` 또는 작업 맥락에 맞게 자동 위임으로 사용합니다.

## 팀 구성 (8 + 총괄)

| # | 에이전트 | 역할 | 호출 키워드 |
|---|----------|------|-------------|
| 1 | `naver-senior-travel-blogger` | 네이버 시니어 여행전문 블로거 — 초안 집필 | 글 써줘, 초안, 포스트 기획 |
| 2 | `travel-journalist` | 여행전문기자 — 팩트체크·취재 보강 | 사실확인, 검증, 취재 |
| 3 | `travel-magazine-editor` | 매거진 편집장(팀장) — 전략·기획·최종 데스크 | 기획, 발행 결정, 검수, 캘린더 |
| 4 | `travel-photographer` | 전문 여행 포토그래퍼 — 샷리스트·이미지 생성 | 사진, 샷리스트, 이미지 |
| 5 | `veteran-designer` | 베테랑 디자이너 — 썸네일·인포그래픽·디자인 시스템 | 썸네일, 디자인, 인포그래픽, 표 |
| 6 | `cardnews-image-md` | 카드뉴스 이미지파트 MD — 카드뉴스 기획·제작 | 카드뉴스, SNS 요약 |
| 7 | `reader-panel-evaluator` | 30·40·50·60대 독자 평가단 — 발행 전 검증 | 평가, 독자반응, 점검 |
| 8 | `ai-prompt-engineer` | 전문 AI 프롬프트 엔지니어 — 프롬프트·템플릿·자동화 | 프롬프트, 템플릿, 자동화 |

> 편집장(3번)이 사실상 팀장/데스크입니다. 큰 일은 편집장에게 먼저 맡기면
> 나머지 에이전트에게 작업을 배분·검수하는 흐름으로 진행할 수 있습니다.

## 표준 제작 파이프라인

```
[0] 전략·기획        편집장: 필러/클러스터 + 키워드 + 시즌 캘린더로 "무엇을 쓸지" 결정
        │
[1] 프롬프트 준비    프롬프트 엔지니어: 이번 글용 집필/이미지 프롬프트 세팅(선택)
        │
[2] 초안 집필        블로거: 네이버 구조 + 시니어 톤으로 완성형 초안 작성
        │            (사진 자리 [사진:...], 메타블록 포함)
        │
[3] 팩트체크/보강    기자: 요금·교통·시설 교차검증 + 취재 디테일 보강
        │
[4] 비주얼           포토그래퍼: 샷리스트/이미지 → 디자이너: 썸네일·인포그래픽
        │                      → 카드뉴스 MD: 카드뉴스(유입 깔때기)
        │
[5] 독자 검증        평가단: 30/40/50/60대 점수 + 이탈 지점 + 개선안
        │
[6] 발행 데스크      편집장: 품질 게이트 통과 시 발행 승인 / 보완 지시 / 반려
```

## 빠른 사용 예시

- "이번 주에 쓸 글 5개를 편집장 관점에서 기획해줘" → `travel-magazine-editor`
- "경주 효도여행 글 초안 써줘" → `naver-senior-travel-blogger`
- "이 초안 요금이랑 교통편 팩트체크 해줘" → `travel-journalist`
- "이 글 썸네일이랑 요약 카드 디자인해줘" → `veteran-designer`
- "본문을 카드뉴스 10장으로 만들어줘" → `cardnews-image-md`
- "발행 전에 연령대별로 평가해줘" → `reader-panel-evaluator`
- "효도여행 글 자동 생성 프롬프트 만들어줘" → `ai-prompt-engineer`

## 발행 지침 (단일 기준 · knowledge/)

실제 발행 품질은 아래 두 지식파일이 **단일 기준(SSOT)**입니다. 에이전트 본문과 충돌하면 이 지침이 우선합니다.

| 지침 | 파일 | 적용 |
|------|------|------|
| 뚜벅이 당일치기 글쓰기 | `knowledge/tukbeoki-blog-writing-guide.md` | 본문(영역1) — 구조·말투·SEO/AEO/GEO·강조 마크·박스·출력 전 15개 점검 |
| witchbloom82 이미지 | `knowledge/witchbloom82-image-guide.md` | 이미지(영역2) — 카드 구성·비율·영문 프롬프트 꼬리표·톤·워터마크 |

- 글은 **2영역 출력**(영역1 본문 + 영역2 이미지 프롬프트)이 원칙입니다.
- 블로그: `blog.naver.com/witchbloom82` (모든 이미지 우하단 워터마크 필수).
- 기존 GPTs 발행 방식과 동일하게 운용하도록 맞췄습니다.

## 공통 원칙 (모든 에이전트가 공유)

1. **시니어 가독성 최우선** — 쉬운 말, 짧은 문단, 큰 글자, 고대비, 핵심 요약 먼저.
2. **네이버 알고리즘 의식** — C-Rank(전문성·일관성), D.I.A.+(직접경험·정보성), 스마트블록(세부 의도 키워드), 체류시간.
3. **정직함** — 과장·낚시·미검증 정보 금지. 단점도 솔직히. AI 생성물은 실제 기록과 구분.
4. **시니어 실용정보 차별화** — 경로 할인, 무장애 시설, 화장실·경사·휴식·교통, 응급 대응을 항상 챙긴다.
5. **모든 결정은 3,000명 목표에 비춘다.**
