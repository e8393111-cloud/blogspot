# 발행 성과와 기존 글 보강 — 2026-09-11 적용

사용자 요청: 조회수·유입경로를 근거로 즉시 보강과 근본적인 제작 방식을 함께 개선한다.
적용 대상: witchbloom82 여행글. 러닝 저장소·Blogger·사이트 코드는 이 작업에서 수정하지 않는다.

## 작업 전에 읽을 것

- `baseline-2026-09-11.json`: 실제 네이버 통계 화면에서 읽은 기준값. 월 조회수와 유입 비중의 분모는 다르다.
- `recovery-queue.json`: 우선 보강 대상, 확인 상태, 수정 이력. 수치를 모르면 null로 둔다.
- `patches/`: 기존 원문에 삽입/교체할 문단과 검증 근거. 완성 원고·임시저장·발행과 구분한다.
- `post-record.template.json`: 신규 글과 기존 글 수정 모두에 사용하는 기록 양식.
- `HANDOFF-2026-09-11.md`: 이번 변경 결과와 다음 실제 작업.

## 제목·기획

1. 핵심 독자 질문을 한 문장으로 적고 제목·도입·3초요약이 같은 질문에 답하게 한다.
2. 실제 블로그 유입 검색어, 기존 글 성과, 현재 검색량, 시의성, 취재 가능성을 함께 판단한다.
3. `가볼만한곳`을 무조건 우선하거나 `당일치기`·`차 없이`·`뚜벅이`를 일괄 금지하지 않는다. 검색량이 크다고 우리 글의 노출·클릭이 늘어난다는 인과는 확인되지 않았다.
4. 이미 검색 유입이 있는 제목은 보존이 기본. 제목 변경은 기존 유입과 본문 일치도를 확인한 소수 글에서만 시험한다. 제목·본문·이미지를 한꺼번에 바꾸고 한 요소의 효과라고 결론 내리지 않는다.
5. 계절·축제와 상시 교통·코스 글을 함께 기획한다. 비율은 고정 정답이 아니며 효과를 보고 조정한다. 계절 글은 공식 일정·종료 이후 안내까지 관리한다.
6. 허브글은 검색 유입뿐 아니라 기존 독자의 선택·추가 열람을 돕는 목적도 있다. 검색량 하나로 배제하지 않는다. 같은 지역도 서로 다른 질문이면 후속 글을 만들 수 있으나 동일 원고 재포장은 금지한다.

## 내용·형식 보존

- 기존 3초요약·이모지·소제목·단락·폰트·강조색·장소 카드·이미지·실제 링크를 보존한다. 내용 보강 요청을 전체 서식 변경으로 해석하지 않는다.
- 핵심 답을 먼저 주고 부가 설명의 비중을 조절한다. 교통 질문이면 마지막 도보·복귀까지, 예매 질문이면 구매 조건까지, 코스 질문이면 이동과 체류를 합친 일정을 해결한다.
- 기존 글의 식사·카페를 임의로 삭제하지 않는다. 신규 세부 질문 글에서는 핵심 질문과 무관한 식사·카페를 분량 채우기로 강제하지 않는다.
- 원본에서 실제 내부링크가 있는지 먼저 본다. 원주 글에는 정동진·무릉별유천지 링크가 이미 있다. 링크 없음으로 오진하지 말고 연결 이유와 적합성을 개선한다.
- 완독을 유도하려고 답을 뒤로 미루지 않는다. 안내 면책문·훅·요약이 겹쳐 핵심 답이 내려가면 같은 역할의 문장을 통합한다.
- 공식 사실·지도 경로·작성자의 일정 제안·사용자 직접 경험을 구분한다. 직접 경험을 지어내지 않는다. 장식용 AI 이미지로 출구·정류장·입구·지도 증거를 대체하지 않는다.
- 점수 통과는 독자 성과의 증거가 아니다. 점수 때문에 불확실한 버스·요금·막차를 확정하거나 필수 정보를 지우지 않는다. 검수 미달 원고도 아스트라 검수 대상으로 접수하되 실제 결함은 해결·기록한다.

## 상태와 성과 기록

원고완성 → 검수중 → 임시저장 → 발행확인. 보류는 사유를 별도로 적는다.
기존 글 보강은 수정안작성 → 부분검증/검증완료 → 임시저장 → 공개수정확인.
Git 커밋·폴더 날짜·평가 점수를 발행 증거로 쓰지 않는다. 발행확인은 실제 공개 URL·게시일·본문 대조 또는 사용자의 명시적 발행 확인을 기록한다. 날짜가 불명확하면 추정하지 않는다.

- 신규 글: 발행 후 7일·28일 경과의 조회수와 유입 질문을 기록한다. 같은 경과일끼리 비교한다.
- 기존 글: 실제 공개수정일을 기준으로 수정 전 14/28일과 수정 후 14/28일을 비교한다. 수정 당일은 비교 구간에서 제외한다. 수정안 작성일을 기산점으로 삼지 않는다.
- 월간 총조회수, 검색 유입 건수, 홈판 유입 건수, 재방문율, 평균사용시간은 구분한다. 비중만 알면 비중만 기록한다. 전체 조회수×유입비중으로 유입 건수를 만들어내지 않는다.
- 노출수·클릭수가 없으면 CTR을 계산하지 않는다. 평균사용시간을 개별 글 완독률이나 이탈률로 바꾸지 않는다.
- 검색 수요·요일·휴일·행사 종료·다른 글 발행 등 혼재 요인을 함께 적는다. 상승·하락만으로 수정의 인과효과를 확정하지 않는다.
- 조회수 목표는 사용자 목표와 관측값을 분리한다. 통계 조회 불가 시 값을 복사하거나 0으로 채우지 말고 미확인으로 남긴다.

## 매 실행에 연결

기존 실행 루틴은 이 문서와 `recovery-queue.json`을 먼저 읽는다. 수행 가능한 긴급 사실 정정·미완료 보강·기한이 도래한 성과 점검을 신규 주제보다 먼저 검토한다. 자료가 없으면 필요한 자료/접근 조건을 기록하고 가능한 원고 작업은 진행한다.
이 파일 작성만으로 예약 작업이나 네이버 자동 발행이 생성되는 것은 아니다. 기존 루틴의 실행 본체에 읽기 단계를 연결하며, 실제 실행 결과를 별도 기록한다.
