# 00_여행블로그_MASTER — 세션 시작 필수 기준

> 이 파일은 여행 블로그 프로젝트의 **세션 부트스트랩 파일**이다.
> 과거 대화 기억이나 요약만으로 작업하지 않는다. 모든 여행 블로그 작업은 아래 로딩 순서를 먼저 수행한 뒤 시작한다.

---

> 최신 공통 지침은 지정 브랜치의 MASTER와 01~05 실행 문서에 고정한다. 첨부 사본·옛 문서의 상충하는 우선순위와 실행 방식은 이 MASTER의 로딩 순서·우선순위를 따르며 재활성화하지 않는다.

## 0. 절대 원칙 — 기억 기반 작업 금지

- 이전 채팅에서 봤다는 이유만으로 현재 규칙·원고·이미지 상태를 안다고 가정하지 않는다.
- 사용자가 같은 규칙을 다시 설명하게 만들지 않는 것이 목표다.
- 정확한 형식, 이미지 소스, 현재 진행 상태는 **프로젝트 소스 + Git 상태 파일**에서 다시 읽는다.
- 필요한 파일에 접근할 수 없으면 추측해서 진행하지 말고, 무엇이 열리지 않는지만 짧게 보고한다.

### 실행 전 체크포인트
아래 6개가 확인되기 전에는 이미지 생성이나 Work 실행 지시를 시작하지 않는다.
- 대상 글이 맞는가
- 기존 네이버 임시저장본이 있는가
- 현재 완료/미완료 상태가 무엇인가
- 본문 최신본이 무엇인가
- 이미지 실제 소스와 디자인 레퍼런스가 무엇인가
- 이번 요청에서 사용자가 유지/수정하라고 한 요소가 무엇인가

하위 문서가 스스로 “최우선/단일 기준”이라고 한 옛 문구로 이 순위를 바꾸지 않는다.

## 3. Chat / Git / Work 역할

### 메인 Chat
- 장기 규칙 수정, 예외 복구, Work 실패 분석, 사용자가 별도로 요청한 제작·검수 담당.
- 정상 발행 작업을 매번 Chat에서 쪼개 처리하지 않는다.

### Git
- 장기 규칙과 글별 실제 작업 상태의 기준점이다.
- 중앙 발행 기록은 `.claude/PUBLISHED-REGISTRY.md`에 유지한다.
- 글별 `STATUS.md`가 있으면 함께 유지한다.

### Work
- **기본 발행 실행 주체**다.
- 브라우저 연결이 정상이라면 Git/소스 확인부터 원고·이미지·네이버 작성·최종검수·발행·Git 기록까지 한 번에 끝내는 것을 우선한다.
- 기존 임시저장본이 있으면 중복 새 글 생성 금지.
- 같은 UI 동작 2회 실패 시 동일 행동을 반복하지 말고 안전한 대체 방식으로 전환한다.
- 사용자가 `임시저장만` 또는 `발행 금지`를 명시하지 않았다면 자동화 실행의 기본 목표는 공개 발행까지다.

## 4. 표시 형식의 단일 실행 기준
`01_TRAVELBLOG_RENDER_SPEC.md`를 따른다. 본문·강조·인용구·상단 순서·링크·장소·CTA·표 형식을 새 Work마다 바꾸지 않는다. 실제 예시는 05에서 확인된 요소만 사용한다.

## 5. 이미지의 단일 실행 기준
`02_TRAVELBLOG_IMAGE_SPEC.md`를 따른다. 상세 근거는 이미지 V2, 실제 권리는 사진별 CREDITS와 원출처를 확인한다. 2회 원본 왜곡이면 재생성을 끝내고 원본 그대로+본문 텍스트로 전환한다. 옛 결정론적 조판 fallback은 사용자 별도 요청 없이는 적용하지 않는다.

## 6. 실행과 완료 기준
`03_WORK_EXECUTION_ROUTINE.md`의 Work-first 순서로 실행하고 `04_FINAL_QA_CHECKLIST.md`로 내부 YES/NO를 기록한다. 공개/저장 결과와 Git 기록까지 확인한 뒤 완료 처리한다. 05는 사실 관측과 새 규격의 차이를 명시한 예시 문서다.

## 7. 글별 STATUS.md 운영 규칙

모든 진행 중 글은 폴더에 `STATUS.md`를 둔다.

STATUS에 반드시 포함:
- 네이버 계정/블로그
- 글 제목
- Git 원고 경로/브랜치
- 현재 네이버 상태(미작성/임시저장/발행)
- 마지막으로 실제 확인한 시각
- 완료된 항목
- 미완료/문제 항목
- 사용자 승인/비승인 요소
- 다음 실행에서 할 일
- 절대 금지사항
- 마지막 Work 실패 지점

### 업데이트 시점
- 임시저장 성공
- 사용자 피드백으로 디자인/서식 기준이 바뀜
- 이미지 승인/폐기
- 링크/본문 대규모 수정
- Work 실패로 다음 시작점이 바뀜
- 공개 발행 완료

## 8. Work 실행 패킷 규칙

Work 지시문은 다음만 포함한다.
- 정확한 대상 글/기존 임시저장본
- 읽을 STATUS 경로
- 이번 실행에서 할 변경
- 하지 말아야 할 것
- 종료 조건(임시저장/재열기 검수)
- 2회 실패 중단 규칙

정상 실행은 03의 Work-first를 따른다. 이미 확인한 내용의 불필요한 재조사·재기획은 하지 않는다.

---

## 9. 사용자의 반복 설명을 막기 위한 자기점검

사용자가 다음과 같은 표현을 하면 즉시 장기 규칙 후보로 판단한다.
- `전에 말했잖아`
- `기존 글이랑 왜 달라`
- `소스에 적혀 있잖아`
- `또 같은 말 해야 해?`
- `앞으로 계속 이렇게`

이 경우:
1. 현재 작업을 바로 밀어붙이지 않는다.
2. 관련 소스/Git을 다시 읽는다.
3. 장기 규칙이면 MASTER/운영지침에 반영한다.
4. 글별 문제면 STATUS에 반영한다.
5. 사용자에게 같은 규칙을 다시 장황하게 설명하게 하지 않는다.

## 11. 자동화 우선 모드 — 2026-09-16 확정

- 사용자가 `다음 글`, `진행`, `계속`, `이어줘`, `발행해줘`처럼 시작 신호를 주면, 별도 범위 제한이 없는 한 **한 글 전체 파이프라인을 끝까지 진행**한다.
- 단계별 승인 질문을 기본값으로 두지 않는다. 중간에 사용자에게 파일 찾기·재업로드·같은 규칙 재설명을 반복 요구하지 않는다.
- 사용자 개입은 로그인/보호조치/비공개 원본 접근/권리 문제/근거로 해소할 수 없는 사실 충돌처럼 사람이 꼭 필요한 예외에만 요청한다.
- 이미지 제작은 개별 승인 대신 자체검수한다. `area2 + CREDITS + 이미지지침`을 기준으로 비율·문구·장소·출처·패널 금지·모바일 가독성을 확인한다. 같은 이미지의 원본 왜곡이 누적 2회면 재생성을 중단하고 02의 실제 원본 그대로+본문 정보 fallback으로 전환한다.
- 매 글마다 디자인을 새로 발명하지 않고 승인된 여행 블로그 카드 구조를 재사용한다. 사용자가 `이번 글만`이라고 한 이미지는 장기 템플릿으로 승격하지 않는다.
- **한 글당 Work 1회**를 목표로 한다. 같은 Work 안에서 네이버 입력 전에 본문·서식·링크·이미지·삽입순서·종료조건을 확정한다.
- Work 지시문은 항상 **PLAIN TEXT / 바로 복붙 가능 형식**으로 제공한다.
- 이 프로젝트의 장기 목표는 `알아서 발행하는 자동화`다. 사용자가 `임시저장만`, `발행 금지`, `검수 후 승인`이라고 명시하지 않은 신규 자동화 실행은 자체검수 후 공개 발행까지를 기본 목표로 한다.
- 정상 완료 보고는 제목 / 발행 상태 / 최종 확인 시각 / 예외(있을 때만)만 짧게 보고한다.
- **사용자를 중간 감독자로 쓰지 않는다.** 한 글 처리 중 Chat ↔ Work ↔ File Library ↔ 사용자 확인을 반복 왕복하는 흐름은 실패한 자동화로 간주한다.
- 한 글에서 같은 종류의 수정/확인 루프가 2회 발생하면 세 번째 반복 전에 방식을 단순화한다. 예: 이미지 편집 반복 → 02의 원본 그대로+본문 텍스트, 링크 미리보기 반복 → 일반 클릭 링크, Work UI 반복 → 현재 안전 상태 저장 후 다음 단일 실행 패킷으로 정리.
- 글 하나를 완료하기 위해 사용자가 여러 Work 창을 열거나 같은 파일을 반복 첨부하게 만들지 않는다. 이미 Git/File Library/프로젝트 소스에서 확보된 자료는 시스템이 다시 찾는다.
- 자동화 성공 기준은 `작업을 많이 했다`가 아니라 **사용자 개입 최소 + Work 최소 + 한 번에 임시저장/발행 완료**다.
- 담양처럼 예외 복구 작업에서 생긴 장시간 왕복·재생성·다중 Work 사용은 정상 운영 패턴으로 재사용하지 않는다.
- 세부 자동화 규칙은 Git `.claude/00A_여행블로그_AUTOMATION_FIRST.md`를 따른다.
