# 00_여행블로그_MASTER — 세션 시작 필수 기준

> 이 파일은 여행 블로그 프로젝트의 **세션 부트스트랩 파일**이다.
> 과거 대화 기억이나 요약만으로 작업하지 않는다. 모든 여행 블로그 작업은 아래 로딩 순서를 먼저 수행한 뒤 시작한다.

---

## 0. 절대 원칙 — 기억 기반 작업 금지

- 이전 채팅에서 봤다는 이유만으로 현재 규칙·원고·이미지 상태를 안다고 가정하지 않는다.
- 사용자가 같은 규칙을 다시 설명하게 만들지 않는 것이 목표다.
- 정확한 형식, 이미지 소스, 현재 진행 상태는 **프로젝트 소스 + Git 상태 파일**에서 다시 읽는다.
- 필요한 파일에 접근할 수 없으면 추측해서 진행하지 말고, 무엇이 열리지 않는지만 짧게 보고한다.

---

## 1. 모든 작업 시작 전 필수 로딩 순서

여행 블로그 관련 요청을 받으면 답변/생성/Work 지시 전에 다음 순서로 확인한다.

### A. 공통 기준
1. 프로젝트 소스의 `00_여행블로그_MASTER.md` (이 파일)
2. 프로젝트 소스의 `여행블로그_운영지침_통합본.md`
3. 이미지 작업이 포함되면 프로젝트 소스의 `blog-image-project-instructions(1).md`

### B. Git 대상 글
4. 저장소 `e8393111-cloud/blogspot`
5. 기본 브랜치 `claude/blog-agents-seniors-bdb75n` (사용자가 다른 브랜치 지정 시 그 지정 우선)
6. 해당 글 폴더의 `STATUS.md` — **가장 먼저 읽는 현재 상태 파일**
7. `area1.md` — 본문/링크/삽입 위치
8. 이미지 작업이면 `area2.md` + `photos/CREDITS.md` + 실제 접근 가능한 레퍼런스 파일
9. `FACTS.md`, `NOTES.md`, `TODO-운영자.md`, `RECOVERY*.md`는 필요한 경우 추가 확인

### C. 실행 전 체크포인트
아래 6개가 확인되기 전에는 이미지 생성이나 Work 실행 지시를 시작하지 않는다.
- 대상 글이 맞는가
- 기존 네이버 임시저장본이 있는가
- 현재 완료/미완료 상태가 무엇인가
- 본문 최신본이 무엇인가
- 이미지 실제 소스와 디자인 레퍼런스가 무엇인가
- 이번 요청에서 사용자가 유지/수정하라고 한 요소가 무엇인가

2. 해당 글/이미지에서 사용자가 이미 승인한 유지 조건

4. `여행블로그_운영지침_통합본.md`
5. `blog-image-project-instructions(1).md`
6. 해당 글의 `STATUS.md`와 `RECOVERY*.md`

사실관계 충돌은 순위로 덮지 말고 근거를 확인한다.

## 3. Chat / Git / Work 역할

### 메인 Chat
- 판단·검수·사실확인·이미지 준비·링크 정리·최종 실행 패킷 작성
- Work를 열기 전에 가능한 준비를 모두 끝낸다.

### Git
- 장기 규칙이 아니라 **글별 실제 작업 상태의 기준점**이다.
- 각 글 폴더에 `STATUS.md`를 유지한다.
- 작업이 끝나거나 중요한 상태가 바뀌면 STATUS를 갱신한다.

### Work
- 브라우저 손발 역할만 한다.
- 새 조사/기획/이미지 스타일 결정/Git 전체 탐색 금지.
- 기존 임시저장본이 있으면 새 글 생성 금지.
- 같은 UI 동작 2회 실패 시 즉시 중단.
- 기본 종료점은 임시저장. 공개 발행은 사용자 명시 승인 때만.

## 4. 네이버 여행글 실제 표시 서식 — 고정 기준

- 본문: **15**
- 일반 굵은 강조: **16 + 굵게**
- 분홍 강조: **#F02C8C + 16 + 굵게**
- 큰 소제목: 네이버 **인용구4(quotation_underline) + 19 + 굵게 해제**
- 보조 소제목: 네이버 **인용구2(quotation_line)**
- 3초요약 유지
- ✅ / ★ / 이모티콘 / 짧은 단락 / 빈 줄 구조 유지

### 소제목 번호 규칙
- 여행 블로그의 네이버 표시 소제목 앞에 `1.`, `2.`, `3.` 같은 숫자를 자동으로 넣지 않는다.
- Git 원고의 숫자는 작성 구조용일 수 있으므로 **실제 승인된 네이버 스타일을 우선**한다.
- 사용자가 특정 글에서 번호를 명시적으로 원한 경우만 예외.

### 하이라이트 주의
- 러닝글 전용 형식을 여행글에 섞지 않는다.
- 여행글에 배경색 하이라이트를 자동 생성하지 않는다. 실제 승인된 공개글/사용자 지정만 복제한다.

## 5. 이미지 제작 — 필수 사전 확인

이미지 생성 전에 반드시:
1. `blog-image-project-instructions(1).md`를 읽는다.
2. 해당 글 `area2.md`를 읽는다.
3. `photos/CREDITS.md`와 실제 장소/제품 레퍼런스를 직접 확인한다.
4. 디자인 레퍼런스와 실제 장소 사진의 역할을 구분한다.

### 금지
- 실제 소스가 있는데 임의의 장소 배경을 새로 만들어 대체하지 않는다.
- 레퍼런스를 실제 입력으로 쓰지 않고 기억/텍스트 설명만으로 재현하지 않는다.
- 글라스패널, 반투명 흰 박스, 뿌연 흰 그라데이션, 글자 뒤 안개/블러, 그림자, 외곽선, 글로우 금지.
- 사용자 승인 전에 `최종 이미지`라고 기록하지 않는다.

### 기본 스타일
- 실제 사진이 주인공인 풀배경
- 기존 `무릉별유천지 입장권` 카드의 타이포그래피를 시각 기준으로 사용
- 사진 위 자연 여백에 글자를 직접 배치
- 핵심 숫자/한 줄만 포인트색
- 광고용 과도한 블랙체 금지
- 한 이미지 한 장면

## 6. 링크 규칙

- `[버튼링크:...]` 마크업을 네이버에 그대로 남기지 않는다.
- raw URL만 덩그러니 남은 상태를 완성으로 보지 않는다.
- 가능한 경우 실제 URL을 네이버 네이티브 링크 미리보기로 변환한다.
- 기존 여행글 내부링크는 실제 공개 URL이 확인된 것만 사용한다.
- 링크 실패를 숨기지 말고 STATUS에 기록한다.

---

## 7. 글별 STATUS.md 운영 규칙

모든 진행 중 글은 폴더에 `STATUS.md`를 둔다.

STATUS에 반드시 포함:
- 네이버 계정/블로그
- 글 제목
- Git 원고 경로/브랜치
- 현재 네이버 상태(미작성/임시저장/발행)
- 마지막으로 실제 확인한 시각
- 완료된 항목
- 미완료/문제 항목
- 사용자 승인/비승인 요소
- 다음 실행에서 할 일
- 절대 금지사항
- 마지막 Work 실패 지점

### 업데이트 시점
- 임시저장 성공
- 사용자 피드백으로 디자인/서식 기준이 바뀜
- 이미지 승인/폐기
- 링크/본문 대규모 수정
- Work 실패로 다음 시작점이 바뀜
- 공개 발행 완료

---

## 8. Work 실행 패킷 규칙

Work 지시문은 다음만 포함한다.
- 정확한 대상 글/기존 임시저장본
- 읽을 STATUS 경로
- 이번 실행에서 할 변경
- 하지 말아야 할 것
- 종료 조건(임시저장/재열기 검수)
- 2회 실패 중단 규칙

Work에 장문의 조사나 이미지 기획을 다시 시키지 않는다.

---

## 9. 사용자의 반복 설명을 막기 위한 자기점검

사용자가 다음과 같은 표현을 하면 즉시 장기 규칙 후보로 판단한다.
- `전에 말했잖아`
- `기존 글이랑 왜 달라`
- `소스에 적혀 있잖아`
- `또 같은 말 해야 해?`
- `앞으로 계속 이렇게`

이 경우:
1. 현재 작업을 바로 밀어붙이지 않는다.
2. 관련 소스/Git을 다시 읽는다.
3. 장기 규칙이면 MASTER/운영지침에 반영한다.
4. 글별 문제면 STATUS에 반영한다.
5. 사용자에게 같은 규칙을 다시 장황하게 설명하게 하지 않는다.
