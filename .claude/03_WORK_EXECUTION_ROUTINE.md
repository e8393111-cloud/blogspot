# 03 — Work-first 실행 순서
개정: 2026-09-29. 역할: **어떤 순서로 실행하는가**. 표시값은 01, 이미지 판단은 02, 판정 항목은 04, 실측 예시는 05에만 둔다.

## 범위 먼저 고정
사용자 요청의 대상·유지 조건·금지 사항·종료점부터 확인한다. Git 문서만 작업하는 요청이면 네이버 작성·수정·저장·발행 단계는 수행하지 않는다. 공개글 열람 허용은 편집 허용이 아니다.

## STEP 1 — 공통 소스 읽기
CLAUDE 시작점을 확인하고 MASTER의 11단계 로딩 순서를 그대로 수행한다.
필수: MASTER → AUTOMATION_FIRST → PUBLISHED-REGISTRY → RENDER_SPEC → IMAGE_SPEC → 이 WORK_ROUTINE → FINAL_QA → GOLDEN_SAMPLE → 운영지침 → 이미지 V2. 이름이 비슷한 첨부 사본보다 현재 지정 브랜치를 읽는다.

## STEP 2 — 대상 글 확인
정확한 폴더의 area1, area2, photos/CREDITS 및 실제 원본, STATUS(있으면)를 확인한다. FACTS/NOTES/RECOVERY는 필요한 경우 추가한다. 폴더 날짜를 공개일로 간주하지 않는다.

## STEP 3 — 네이버 상태 확인
같은 제목 공개글·임시저장을 실제 목록에서 대조한다. 기존 임시저장이 있으면 신규 작성 금지. 공개글이 있으면 신규 중복 발행 금지; 현재 요청에 공개글 수정 권한이 있을 때만 그 글을 수정한다. 상태를 확인할 수 없으면 새 글로 우회하지 않는다.

## STEP 4 — 날짜 민감 사실 우선 검수
운영시간·매표/입장/탈것 마감·요금·할인·예약·교통·막차·행사 날짜를 공식 근거로 우선 검증한다. 값·출처·확인일을 남긴다. 미확인 숫자를 추정하지 않는다. 오래된 상시 설명까지 불필요하게 다시 기획하지 않는다.

## STEP 5 — 이미지 준비
02 V3대로 EDIT/GENERATE/RAW/OMIT를 표시한다. 실제 원본과 디자인 샘플을 확인하고 허용 변경·문구·비율·세트색을 area2에 확정한다. 인물/개인정보 제거·보정·배경 편집과 필요 시 신규 생성 허용. 원출처·권리 보존, 패널 금지, 연출/생성 표시 검수. 동일 결함2회면 방법·소스·모드를 전환하고 무조건 RAW로 끝내지 않는다.

## STEP 6 — 네이버 작성
기존 초안이면 수정, 공개글/임시저장이 모두 없고 신규 작성이 요청 범위일 때만 신규 작성. 01 그대로 적용한다. 붙여넣기 후 실제 서식 속성을 확인한다.

## STEP 7 — 링크 적용
공식 링크·내부링크·장소카드를 01의 관련 위치에 넣는다. 링크 목적지와 장소 동일성을 확인하고 fallback/정당한 생략 사유를 기록한다.

## STEP 8 — 이미지 삽입
area1 위치와 대응시켜 삽입하고 대표이미지를 지정한다. 원본 fallback으로 카드 수가 줄었으면 area1/area2 및 STATUS의 최종 대응을 먼저 맞춘다.

## STEP 9 — 최종 QA (발행/저장 전)
04 전 항목을 내부 YES/NO로 점검한다. 종료 후에만 확인할 수 있는 결과 확인·Git 기록 항목은 아직 NO/후속 단계로 두며 전체 완료라고 말하지 않는다. 사전 항목의 결함은 수정 후 재검사한다. 치명적 오류가 남으면 공개 발행하지 않는다.

## STEP 10 — 요청한 종료점 실행
- 발행 요청: 공개 발행 → 공개 페이지에서 제목·본문·서식·사진·링크 및 실제 URL 확인.
- 임시저장 요청: 임시저장 → 목록에서 정확한 제목·저장 시각 확인. 가능하면 같은 저장본 재열기 검수. 자동저장 문구만으로 저장목록 확인을 대체하지 않는다.
- 검수 후 승인 요청: 구체적 검수 결과까지 만들고 승인 전 발행 금지.
실제 결과를 다시 04에 반영한다. 실패 시 저장/발행 성공을 추측하지 않는다.

## STEP 11 — Git 기록 / 완료 판정
STATUS에 실제 상태·확인시각·QA·fallback·남은 문제를 기록한다.
공개 확인 시 PUBLISHED-REGISTRY에 공개일·제목·폴더·확보한 공개 URL을 갱신한다. 임시저장은 발행 행을 새로 만들지 않고 STATUS에 기록하며, 레지스트리의 기존 상태와 모순이 있는 경우에만 근거로 정정한다.
URL을 못 얻었으면 미확인으로 기록한다. Git 반영 확인 뒤 04의 최종 항목까지 채워 완료 보고한다.

## 효율 규칙
한 글 = Work 1회가 목표. 한 Work에서 읽기부터 Git 기록까지 수행한다. 사용자를 중간 감독자로 만들지 않으며 이미 확보된 자료를 재업로드시키지 않는다.
같은 UI 동작 2회 실패 시 방식 변경. 링크/이미지는 01/02의 fallback을 적용한다. UI 연결 장애는 현재 저장 여부와 미완료 지점을 기록하며 미저장 내용을 버리는 이동을 하지 않는다.
Chat ↔ Work ↔ File Library 왕복 반복 금지. 치명적 오류가 아닌 미세한 디자인 취향을 이유로 무한 반복하지 않는다.
