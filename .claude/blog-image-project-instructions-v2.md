# 블로그여행글 이미지 제작 지침

## ★ V2 최우선 규칙 — 2026-09-22

> 이 섹션은 아래 기존 규칙보다 우선한다. 충돌 시 V2를 따른다.

### 1. 제작 도구 고정
- 여행 블로그의 **최종 이미지 생성·편집은 GPT 이미지 생성/편집 기능으로만 처리한다.**
- 다른 외부 이미지 생성 도구를 최종 제작 경로로 사용하지 않는다.
- Work에서 이미지까지 한 번에 처리하는 경우에도 동일하게 GPT 이미지 생성/편집 기준을 적용한다.
- 사용자가 별도로 다른 도구를 명시적으로 지정한 경우에만 예외다.

### 2. 실제 사진 우선 — 배경 재생성 금지
- 실제 장소 사진이 확보되어 있으면 그 사진을 **실제 입력 이미지로 사용**한다.
- 실제 사진이 있는데 비슷한 장소를 새로 생성하거나, 사진을 참고해 새로운 배경을 그리는 것은 금지한다.
- 결과물의 장소·산·하늘·길·꽃·건물·사람·시설 배치가 원본과 달라지면 실패다.
- 실제 사진을 쓸 때 GPT의 역할은 **사진 편집**이지 **장면 재창작**이 아니다.

### 3. 실제 사진에서 허용되는 수정
- 비율에 맞춘 크롭과 리사이즈
- 밝기·대비·채도·색온도의 미세 보정
- 자연스러운 수평·구도 정리
- 정확한 카드 문구·워터마크·출처 추가
- 모바일 가독성을 위한 텍스트 위치·크기·줄바꿈 조정

아래 수준을 넘기지 않는다.
> **실제 사진 그대로 보이되, 블로그 카드로 보기 좋게 살짝 다듬은 정도**

### 4. 실제 사진 편집에서 절대 금지
- 하늘·산·나무·꽃·길·건물·사람·차량·버스·표지판·시설의 생성/삭제/교체
- 계절 또는 날씨 변경
- 꽃·단풍·눈·안개 양을 과장
- 원본에 없는 호수·산책로·정류장 등 추가
- 글라스패널, 반투명 박스, 흰 정보면
- 뿌연 흰 그라데이션, 국소 미백, 글자 뒤 안개·블러·글로우
- 과한 HDR·샤픈·채도·주황/골드 색조 통일
- 실제 사진을 일러스트·렌더·AI 합성처럼 보이게 만드는 스타일 변환

### 5. 디자인 V2 방향
- **여행 매거진형 + 감성 엽서형 + 정보카드형의 중간**을 기본으로 한다.
- 사진이 화면의 주인공이고 텍스트는 보조 역할을 한다.
- 현대적이고 단정한 고딕을 사용하며, 관공서 안내판·광고 전단지·과한 포스터 느낌을 피한다.
- 핵심 문구 1줄 또는 핵심 숫자만 포인트색으로 강조한다.
- 한 카드에 색을 많이 쓰지 않는다. 글별 포인트색 1개를 유지한다.
- 불필요한 아이콘·잎 장식·곡선·스티커·말풍선·체크표시를 자동 추가하지 않는다.
- 여백과 글자 크기 차이로 정보 위계를 만든다.

### 6. 기본 템플릿
- 썸네일: 1:1 / 후킹 문구 2~3줄 / 실제 사진 중심
- 정보카드 A: 4:5 / 교통·입장료·핵심 정보
- 정보카드 B: 3:4 또는 4:5 / 이동·주의사항·설명형
- CTA: 16:9 / 실제 사진 + CTA 1~2줄
- 글별 `area2.md`에 비율이 지정되어 있으면 그 값을 우선한다.

### 7. GPT 편집 성공 판정
다음 조건을 모두 통과해야 사용할 수 있다.
- 원본 실제 장소가 그대로 유지됨
- 원본에 없던 요소가 생기지 않음
- 문구·숫자·비율이 지시서와 일치함
- 글자 뒤 패널·미백·안개·글로우가 없음
- 원저작자 워터마크·출처가 훼손되지 않음
- 모바일에서 읽기 쉬움
- 카드 세트가 같은 디자인 언어를 사용함

**결과가 '실제 사진에 디자인을 얹은 것'이 아니라 'AI가 새 풍경을 만든 것'처럼 보이면 즉시 실패 처리한다.**

### 8. 2회 실패 fallback
- 같은 실제 사진 편집에서 배경 변형이 2회 발생하면 동일 프롬프트로 세 번째 생성하지 않는다.
- 우선순위:
  1. 실제 원본을 그대로 사용하는 방향으로 편집 강도를 낮춘다.
  2. 텍스트 양을 줄이거나 위치를 바꾼다.
  3. 그래도 원본 보존이 안 되면 **실제 원본 사진을 그대로 삽입하고 정보는 네이버 본문 텍스트로 처리**한다.
- 예쁜 가짜 배경보다 실제 사진의 정확성을 우선한다.

### 9. 자동화와의 연결
- 사용자에게 이미지마다 승인받는 흐름을 기본값으로 두지 않는다.
- Work-first 자동화에서도 위 기준을 자체검수하고 통과한 이미지만 사용한다.
- 이미 Git/프로젝트 소스에 확보된 원본을 사용자에게 다시 업로드하라고 요구하지 않는다. 시스템이 먼저 검색한다.
- 사용자가 이미지 스타일에 피드백을 주면 장기 규칙이면 이 파일에 반영하고, 글 하나에만 해당하면 해당 글 `STATUS.md`에 기록한다.


## 목적과 역할
클로드는 여행 원고와 이미지 기획을 작성하고 원고·지시서·레퍼런스를 Git에 올린다. ChatGPT는 Git에서 해당 자료를 읽고, 본문의 이미지 삽입 영역에 맞는 완성 이미지를 생성하여 전달한다. 사용자가 이미 Git에 올린 자료를 다시 업로드하도록 요구하지 않는다.

- 최신 커밋이라고 무조건 대상 원고로 선택하지 않는다. 사용자 지정 글, 원고 발행일, 파일명을 대조한다. ‘오늘’은 한국 시간 기준이다. 후보가 여러 개이고 구분할 근거가 없을 때만 짧게 질문한다.
- Git 업로드만으로 자동 실행되는 것으로 설명하지 않는다. 별도 자동화가 없는 한 사용자 요청 시 작업한다.
- 이미지 제작 요청만으로 원고 수정·커밋·푸시·블로그 발행을 수행하지 않는다.

## 지침 적용 순서
1. 사용자의 현재 명시적 요청과 수정 사항
2. 사용자가 승인한 해당 이미지의 유지 조건
3. 이 프로젝트 지침과 사용자가 제공한 디자인 레퍼런스
4. 해당 글의 이미지 제작 지시서
기존 지시서에 글라스패널·그림자 등의 표현이 있어도 아래 금지 기준을 적용한다. 충돌을 이유로 매번 승인을 요구하지 말고, 디자인 충돌은 이 기준으로 해결한다. 사실 충돌은 확인하거나 사용자에게 정확히 설명한다.

## 입력 확인
원고 전체와 번호별 이미지 지시서를 읽고, 다음을 대조한다.
- 본문의 삽입 위치와 이미지 번호·용도
- 정확한 삽입 문구와 숫자
- 이미지 비율
- 실제 장소·제품 사진의 경로 또는 URL
- 디자인 참고 이미지의 경로 또는 URL
지시서의 파일명은 정해진 이름을 가정하지 말고 저장소에서 찾는다. 링크만 읽고 참조 이미지를 확인했다고 말하지 않는다. 로컬 이미지도 직접 열어 본다.

실제 장소 사진은 장소·계절·장면의 근거다. 디자인 레퍼런스는 글자 모양·굵기·정보 위계·여백의 근거다. 두 역할을 혼동하지 않는다. 참조 사진이 야간이거나 다른 장소인 경우 임의로 낮의 해당 장소 사진이라고 사용하지 않는다. 확인된 대체 자료가 없으면 필요한 자료만 요청한다.

## 디자인 기준
### 사진과 배치
- 자연광 사진이 주인공인 풀배경 이미지. 한 이미지에 한 장면.
- 정보는 사진 여백의 왼쪽 또는 오른쪽에 세로로 정돈한다.
- 사용자가 승인한 세로 구성을 폰트 수정만으로 가로 구성으로 바꾸지 않는다.
- 사진·문구·위치·비율 중 무엇을 유지해야 하는지 먼저 정하고, 요청된 요소만 수정한다.
- 실제 장소의 주요 지형·시설을 임의로 추가하거나 바꾸지 않는다. AI 편집 결과를 원본 사진과 완전히 동일하다고 단정하지 않는다.
- 과장된 채도·HDR·인위적인 구름·과도한 선명화는 피한다.

### 절대 금지: 글자 뒤 배경 효과
- 글라스패널, 유리 효과, 프로스트 효과
- 반투명 흰 박스, 불투명 정보 박스, 크림색 정보면
- 뿌연 흰 그라데이션, 국소적인 미백, 글자 뒤 안개·블러
- 상단·하단 정보 띠, 둥근 스티커·말풍선
패널 테두리를 없애도 뿌연 흰 처리가 남으면 실패다. 사진 위에 글자만 직접 배치한다. 가독성이 나쁘면 자연스러운 여백, 글자 위치·색·줄바꿈을 조정한다. 패널을 다시 넣지 않는다.

### 타이포그래피
- 사용자가 제공한 ‘무릉별유천지 입장권’ 기존 블로그 카드를 시각 기준으로 삼는다. 정확한 서체명은 이미지로 확정하지 않는다.
- 제목: 단정하고 탄탄한 현대적 고딕. 짧은 줄바꿈과 밀도 있는 조합. 지나치게 두꺼운 광고용 블랙체도, 가늘고 밋밋한 안내문체도 피한다.
- 본문: 또렷한 중간 굵기 고딕. 숫자·한글의 획과 자간을 균일하게 한다.
- 핵심 숫자만 크기·색으로 강조한다. 모든 제목과 숫자를 크게 만들지 않는다.
- 짧은 감성 문구 한 줄만 섬세한 손글씨로 사용 가능. 손글씨를 본문·시간표에 쓰지 않는다. 작은 하트나 잎은 선택적으로 한 개 정도만 쓴다.
- 그림자·외곽선·글로우·입체 글씨·글자 그라데이션 금지.
- 굵기와 간격으로 위계를 만든다. 반복 체크표시·별표·아이콘으로 정보를 채우지 않는다.
- Pretendard를 무조건 정답으로 고정하지 않는다. 참고 카드와의 시각적 일치가 우선이다.
- 실제 폰트를 사용했다고 설명하려면 실제 폰트 파일로 조판해야 한다. 이미지 생성에 폰트명을 적은 것은 실제 폰트 적용을 보장하지 않는다.
- 기본 이미지 생성·수정은 이미지 생성 기능으로 한다. 사용자가 실제 폰트 직접 조판을 요청하거나 승인한 작업에서는 글자 없는 배경에 실제 폰트를 합성할 수 있다.

### 색과 여백
- 한 글의 카드 전체에서 포인트색 한 가지를 유지한다.
- 철원 현재 세트는 차분한 로즈 계열을 사용한다. 무릉별유천지 참고 이미지의 보라색을 자동으로 가져오지 않는다.
- 포인트색은 핵심 숫자·일부 제목·얇은 구분선·손글씨에 제한적으로 쓴다.
- 밝은 사진에는 짙은 글자, 어두운 부분에는 밝은 글자를 사용한다.
- 관련 정보끼리 묶고 충분한 여백을 둔다. 정보가 많으면 글자를 무작정 줄이지 말고 비율이나 정보 구성을 검토한다. 사용자 승인 없이 중요한 교통 정보를 삭제하지 않는다.

## 이미지별 형식
원고 지시서의 비율이 있으면 우선 적용한다. 없을 때 기본값:
- 썸네일: 1:1, 제목과 짧은 태그라인만
- 정보 카드: 4:5, 정보량이 많으면 3:4 또는 9:16
- CTA: 16:9
- 우하단 워터마크: blog.naver.com/witchbloom82
- 기존 원저작자 출처·워터마크는 임의로 제거하지 않는다.
- CTA 기본 문구: ‘공감 💗 + 이웃추가’ / ‘뚜벅이 당일치기 코스 꾸준히 올려요’
원고에 없는 CTA 카드를 임의로 늘리지 말고 삽입 위치와 1:1로 대응시킨다.

## 내용 정확성
- 원고의 버스번호·방향·시간·가격·나이 조건·단위를 한 글자씩 대조한다.
- 원고를 읽은 것과 최신 공식 정보 검증을 구분한다. 최신 확인이 필요한 주장에는 공식 자료를 확인한다. 단순 디자인 수정에서 검증하지 않은 원고 수치를 ‘최신 확인 완료’라고 표현하지 않는다.
- 미확인 도보 시간, 막차, 환승 동작, 할인 조건을 만들어 넣지 않는다.
- 교통 카드에는 출발·승차·하차·방향 등 해당 영역에 필요한 행동이 명확해야 한다. 누락을 추측으로 채우지 않는다.
- 이미지별 원문에 모순이 있으면 확인된 근거로 수정안을 제시한다. 원고 자체 변경은 별도 권한 없이 하지 않는다.
- 실제 장소 사진과 다른 장면을 생성하면서 실사 기록 사진인 것처럼 설명하지 않는다.

## 제작 순서
1. 대상 브랜치·원고·이미지 지시서를 확인한다.
2. 삽입 위치와 이미지 번호를 대응시킨다.
3. 해당 번호의 장소 사진과 디자인 레퍼런스를 직접 확인한다.
4. 유지 요소, 변경 요소, 정확한 문구, 금지 요소를 확정한다.
5. 생성 시 레퍼런스 이미지를 실제 입력으로 제공한다. 기억이나 문장 설명만으로 대체하지 않는다.
6. 이미지 한 장을 생성하고 결과를 직접 확인한다.
7. 숫자·문구·패널 잔존·글자 모양·모바일 가독성을 점검한다.
8. 오류가 있으면 해당 오류만 수정하고 최종 이미지를 전달한다.

## 요청 해석과 전달
- ‘이미지 N’, ‘N번’: 해당 번호 한 장.
- ‘하나만 다시’: 직전에 논의한 대상 한 장만 수정.
- ‘전체 생성’: 원고 삽입 위치별 이미지를 각각 별도 파일로 생성. 한 장의 모음 이미지로 합치지 않는다.
- ‘계속’: 직전 승인 범위와 수정 방향을 유지하며 다음 미완료 작업 진행.
- 글라스패널 제거 요청은 패널만 제거하고 승인된 폰트·문구·구성을 유지한다.
- 사용자에게 긴 프롬프트·제작 설명을 반복하지 않는다. 완성 이미지를 우선 보여준다.
- 생성물이 마음에 든다는 사용자 확인 없이 ‘승인된 최종 스타일’로 기록하지 않는다.

## 현재 합의와 승인 범위
- 사용자는 철원 5번 카드의 세로 구성, 왼쪽 정보와 오른쪽 꽃밭 배치를 선호했다.
- 사용자는 기존 무릉별유천지 카드의 타이포그래피를 참고로 제공했다.
- 사용자는 글라스패널 및 글자 뒤 뿌연 처리를 금지했다.
- 철원 6번 요금·상품권 카드는 사용자가 마음에 든다고 했으므로 별도 수정 요청 없이 다시 만들지 않는다. 그 카드의 체크·별표를 모든 카드에 복제하지 않는다.
- 최근 생성 카드의 개별 폰트가 최종 승인되었다고 가정하지 않는다.

## 프로젝트 소스 구성
이 파일과 함께 시각 레퍼런스 원본 또는 Git 경로 목록을 보관한다.
- 기존 무릉별유천지 입장권 카드: 타이포그래피 기준
- 철원 5번 사용자 선호 구성: 레이아웃 기준
- 글별 실제 사진: 해당 Git 지시서에 경로 지정
경로가 없거나 접근할 수 없는 레퍼런스는 있다고 가정하지 않는다. 새 채팅에서 이 지침과 해당 시각 레퍼런스를 먼저 읽고 작업한다.
