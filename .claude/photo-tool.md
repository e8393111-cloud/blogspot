# 사진 소스 도구 — 관광사진 API로 배경 사진 확보하기

영역2 카드마다 **실재하는 공공누리 사진 URL**을 붙이는 방법이다.
`.claude/image-guide.md` §0이 "포토코리아 1순위, URL 지어내기 금지"라고 정해 놨지만
**지킬 수단이 없어서** 매번 "소스 미확보"로 넘겨 왔다. 그 수단이 이것이다.

> 이 문서는 `.claude/keyword-tool.md`(키워드 실측)와 같은 성격이다 — **매번 다시 돌리는 방법**.

## 무엇을 얻나

| 값 | 의미 |
|---|---|
| `originimgurl` | **원본 사진 URL** (`tong.visitkorea.or.kr/...`) — 그대로 열면 사진이 뜬다 |
| `imgname` | 사진 제목 (예: `강원_철원_고석정국민관광지_전경_04-5.jpg`) |
| `cpyrhtDivCd` | ★**저작권 유형** — 아래 참조 |
| `contentid` | 장소 고유번호. `detailImage2`에 넘길 때 쓴다 |

## ★★가장 중요 — `cpyrhtDivCd`를 반드시 본다

| 값 | 뜻 | 글자 오버레이 |
|---|---|---|
| **`Type1`** | 공공누리 **제1유형** (출처표시) — 상업 이용·**변형 가능** | ✅ **가능** |
| **`Type3`** | 제1유형 + **변경금지** | ❌ **불가** — 얹으면 라이선스 위반 |

**Type3 사진은 글자 없이 원본 그대로만** 본문에 넣을 수 있다.

★2026-09 철원 취재에서 실제로 겪었다 — 맛집 카드 배경으로 쓰려던 **한탄강빵명장이 Type3**였다.
그대로 글자를 얹었으면 위반이었다. **은하수교·순담계곡·송대소·고석정가든도 전부 Type3**다.
같은 지역 안에서도 사진마다 유형이 다르니 **장소 단위가 아니라 사진 단위로** 봐야 한다.

**출처 표기(공공누리 의무)** — 글 안에 한 줄:
```
사진 출처 : 한국관광공사 포토코리아 (공공누리 제1유형)
```

## ★반드시 지킬 4가지 (전부 실제로 겪은 것)

**1. `contentId`는 대문자 I다.** `contentid`로 보내면 통째로 무시되고
`NO_MANDATORY_REQUEST_PARAMETERS_ERROR1(contentId)`가 돌아온다.

**2. Make 배열 인덱스는 1부터다** → `{{6.response.body.items.item[1].contentid}}`.
`[0]`을 쓰면 빈 값이 들어가 위 에러가 난다. (키워드 도구와 같은 함정)

**3. 검색이 0건이면 detailImage2가 반드시 실패한다.** 정상이다.
　모듈 4의 `handleErrors: true`로 흘려보내고, 결과에서 `0장`으로 읽으면 된다.
　**관광지가 아닌 것은 아예 없다** — 터미널·정류장·시내버스·일반 식당은 등재 대상이 아니다.
　철원에서 `동송터미널`·`동서울터미널`·`소문난순대국왕족발`이 전부 0건이었다. 억지로 다른 사진을 붙이지 않는다.

**4. `parseResponse: false` + 뒤에 `json:ParseJSON`.** 바로 파싱하면 값이 안 잡힌다.

## ★6단계 — 사진을 실제로 내려받아 눈으로 보고 첨부한다 (필수)

URL만 넘기면 운영자가 하나씩 열어봐야 한다. **파일을 받아 직접 보고, 원본을 채팅에 첨부**한다.
프록시가 직접 다운로드를 막으므로(`CONNECT tunnel failed, 403`) **Make를 통해 base64 조각으로 가져온다.**

### 흐름
```
1 ParseJSON  [{k:"f1", u:"<사진 URL>"}, ...]          ← 카드에 쓸 사진만, 5~6장
2 Iterator   URL마다
3 HTTP       GET 이미지 (parseResponse=false)
             ★헤더 Referer: https://korean.visitkorea.or.kr/  ← 없으면 막힐 수 있다
4 Iterator   {{split("0,1,2,...,21"; ",")}}            ← 조각 번호
5 AddRecord  key=IMG_<k>_<i>
             {{substring(toString(base64(3.data)); 조각*14000; (조각+1)*14000)}}
```
HTTP는 URL당 1회만 돌고(모듈 3), 조각 나누기만 22번 반복된다. 5장이면 5 HTTP + 110 저장.

### 로컬에서 재조립
```python
# 데이터스토어에서 IMG_* 레코드를 받아 조각 번호 순으로 이어붙인 뒤
open(f"{name}.jpg","wb").write(base64.b64decode(b64))
```

### ★반드시 지킬 4가지 (전부 실제로 겪음)
**1. 잘림을 반드시 검사한다.** 조각이 모자라면 아래쪽이 회색으로 날아간다.
```python
im = Image.open(p); im.load()   # 잘렸으면 여기서 예외
```
　★실제: 승일교 사진을 14조각(=147,000B 상한)으로 받았더니 하단 20%가 잘렸다. 22조각으로 다시 받아 194,038B로 완성.
　마지막 조각 길이가 14000이면 **아직 안 끝난 것**이다. 0이 나올 때까지 조각 수를 늘린다.

**2. 데이터스토어는 1MB다.** 사진 두세 장이면 찬다.
　`Maximum data store size (1024 KiB) will be exceeded` → **재조립이 끝난 `IMG_*` 레코드는 즉시 삭제**하고 다음 장을 받는다.

**3. `_image2_1`(웹용)과 `_image3_1`(썸네일)이 있다.** 썸네일은 17KB라 한 조각에 들어가지만 카드로 쓰기엔 작다. **카드용은 `_image2_1`**.

**4. 받은 사진을 Read로 열어 눈으로 본다.** 이게 이 단계의 진짜 목적이다.

### ★눈으로 봐야만 잡히는 것 — 2026-09 철원에서 셋 다 나왔다
| 무엇 | 실제 사례 |
|---|---|
| **파일명이 내용과 다르다** | `강원_철원_고석정국민관광지_전경`이 실제로는 **인공 폭포**였다. 정자도 꽃밭도 아니다 |
| **사진 안에 글자·간판이 있다** | 고석정 꽃밭 컷 하나에 **"I LOVE CHEORWON" 조형물**이 크게 박혀 있었다 → "사진 안 글자 0" 규칙 위반이라 배경에서 탈락 |
| **이미 워터마크가 있다** | 관광공사 사진은 **우하단에 한국관광공사 워터마크**가 박혀 있다 → 우리 워터마크는 **좌하단**으로 옮긴다 |

★**사진과 카드 문구가 서로 맞는지도 본다.** 나무 그늘 가득한 폭포 사진에 "그늘이 적어요"를 얹으면 독자가 헷갈린다(실제로 그렇게 만들었다가 고쳤다).

### 첨부
`SendUserFile`로 **글자 없는 원본**을 그대로 보낸다. 파일명은 `photo01.jpg`처럼 ASCII로(한글 파일명은 첨부에서 깨진다).
카드별로 어느 사진을 쓰면 되는지, 그리고 위에서 발견한 주의점을 한 줄씩 붙인다.

## 다시 돌리는 법

1. **검색어 교체** — 시나리오 6190253의 모듈 1 `json` 배열을 바꾼다
   (`scenarios_get` → 블루프린트 수정 → `scenarios_update`)
2. **실행** — `scenarios_run` (6190253, responsive true). 검색어 10개에 약 30초
3. **읽기** — `data-store-records_list`(137130) → `TP_<검색어>` 레코드
4. **거르기** — `cpyrhtDivCd`가 `Type1`인 것만 오버레이 배경으로 쓴다
5. **영역2에 붙이기** — 카드마다 **후보 2~3개씩**. 검증상태는 `API 응답으로 확인(사진 미열람)`로 정직히

### 검색어를 고르는 요령
- **관광지 정식 명칭**으로 친다. `고석정 꽃밭` ⭕ / `철원 꽃구경` ❌
- 지역명을 붙이면 오히려 0건이 되기도 한다 (`철원 은하수교` 0건 → `한탄강 은하수교` 10건)
- 맛집은 `contenttypeid=39`로 등재된 곳만 나온다. 대부분 없다고 보면 된다

### 오퍼레이션 예산
검색어 1개당 약 3회. 10개 ≈ 30회. 키워드 실측(155개 ≈ 470회)에 비하면 무시할 수준이다.

## ★사진을 눈으로 확인하는 법

**Claude는 사진을 볼 수 없다.** 프록시가 외부 접속을 막아 URL을 열 수 없고,
API가 주는 건 제목·유형·URL 같은 **텍스트뿐**이다. "이 사진이 카드에 어울리는가"는 판단할 수 없다.

→ 그래서 **후보를 한 장에 모은 HTML을 만들어 운영자에게 보낸다.**
　`<img src="...">`를 격자로 깔고 사진마다 `Type1/Type3`를 색으로 표시하면
　운영자가 스크롤 한 번으로 고를 수 있다. (2026-09-07 철원 78장에 이 방식을 썼다)

→ 그래서 **영문 프롬프트에 장면 묘사를 쓰지 않는다.**
　`a wide-open flower field with pink muhly in soft focus…`처럼 상상한 장면을 적으면
　실제 사진이 다를 때 **모델이 배경을 그 묘사대로 고쳐 그린다.**
　대신 이렇게만 쓴다:
```
Edit the uploaded photograph. Keep the image EXACTLY as-is — do NOT repaint,
redesign, regenerate, restyle or replace any part of the background.
ONLY overlay Korean text and a watermark.
Place the text on whichever area of the photo is naturally brightest and
least busy; if no such area exists, place it across the lower third.
```

## ★2026-09-10 정읍에서 해결 — **사진 다운로드가 처음으로 성공했다** (3연패 종료)

세 번 연속 실패했던 6단계(사진 원본 내려받기)가 이번에 돌았다. 원인은 둘 다 이 문서의 예시 자체에 있었다.

### 원인 1 — `(조각+1)`이 Make에서 **문자열 연결**로 처리된다
이 문서가 적어 둔 `{{substring(toString(base64(3.data)); 조각*14000; (조각+1)*14000)}}`에서
`4.value`는 `split()`이 준 **문자열**이라 `4.value + 1`이 덧셈이 아니라 **연결**이 된다.
`"26" + 1` → `"261"` → 끝 인덱스 `3,654,000`. 그래서 조각 하나가 14,000자가 아니라 **14만 자**로 부풀어
레코드 7개만에 943KB를 먹고 `OutOfSpaceError`가 났다. 세 번의 실패가 전부 이것이다.

**고친 표현식 — 이걸 쓴다**
```
{{substring(toString(base64(3.data)); 4.value * 14000; 4.value * 14000 + 14000)}}
```
`4.value * 14000`이 먼저 숫자로 강제되므로 뒤의 `+ 14000`은 정상적인 덧셈이 된다.

### 원인 2 — 재조립하려고 레코드를 읽으면 **내 컨텍스트가 터진다**
사진 한 장이 base64로 20만 자다. `data-store-records_list` 결과를 그대로 받으면 5만 토큰이 날아간다.
→ **결과가 크면 도구가 알아서 파일로 떨궈 준다.** 그 경로를 python으로 읽어 재조립하면 컨텍스트를 1도 안 쓴다.
```python
recs = json.loads(io.open(저장된_경로, encoding='utf-8').read())
# IMG_<k>_<i> 를 i 순서로 이어붙여 base64.b64decode → .jpg
```

### 시나리오
`🖼 사진 원본 내려받기 (base64 조각)` — id **6219674** (on-demand · 이번에 새로 만들었다)
데이터스토어는 `146191` 공용. **한 번에 2장까지**(30조각 기준 약 400KB). 큰 사진은 33~45조각.

### 조각 수 판정 (문서의 기존 규칙이 맞았다)
- **마지막 조각 길이 0자 = 다 받은 것.** 14,000자면 **아직 안 끝났다** → 조각 수를 늘려 다시.
- 실측: 15만~22만 바이트 사진은 30조각으로 충분. 30만 바이트대는 30조각으로 **잘렸다**(45조각 필요).
- PIL이 이 환경에 없다. 대신 **JPEG 마커로 검사**한다 — `d[:2]==b'\xff\xd8' and d[-2:]==b'\xff\xd9'`.

### ★그리고 눈으로 봐서 실제로 한 장을 걸러냈다
`전북_정읍_우화정_외부_05.jpg`(Type1)를 열어 보니 우화정이 아니라 **캐릭터 포토존 프레임**이었고
사진 안에 글자가 세 곳 박혀 있었다. URL과 유형만 보고 넘겼으면 그대로 배경으로 썼을 컷이다.
**이 단계의 값어치가 여기서 나온다.**
