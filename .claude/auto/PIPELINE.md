# 자동 발행 파이프라인 — 하루 3회 실행 절차

> 이 문서가 Routine의 **실행 지시서 본체**다. 트리거 프롬프트는 "이 파일을 읽고 따르라"만 말한다.
> 절차를 바꾸려면 트리거가 아니라 **이 파일을 고친다.**
> 대상 세션: `session_01Ntjy5x2ZiuamxQwP234PEm` (🤖 여행블로그 자동 파이프라인)
> 발사: `0 23,7,15 * * *` UTC = **KST 08:00 / 16:00 / 00:00**

## ★이 환경에서 확인된 함정 3가지 (2026-09-09 스모크 결과)

1. **★`run_in_background: false`는 먹히지 않는다. 서브에이전트는 무조건 백그라운드로 뜬다.**
   2026-09-09 실행에서 4번 모두 `false`로 호출했는데 4번 다 `Async agent launched`가 돌아왔다.
   → **"포그라운드로 호출한다"는 예전 대책은 폐기한다.** 하네스가 무시하므로 지킬 수가 없다.
   → **대신 이렇게 한다 (실제로 작동한 방법):**
   　 ① 에이전트를 띄우기 **직전에 `send_later`로 자기 체크인을 건다**(취재·집필·평가는 10~15분, 긴 건 50분).
   　 　 `send_later`는 이 세션으로 **확실히 배달된다** — 2026-09-09에 4/4 성공했다. 이게 유일하게 믿을 수 있는 안전줄이다.
   　 ② 완료 알림이 오면 그대로 진행한다(같은 날 4/4 정상 도착했다. **다만 전날엔 0/1이었으니 믿고 놀지 마라**).
   　 ③ 알림이 안 오면 **트랜스크립트 메타데이터만** 본다(전문을 tail 하면 컨텍스트가 터진다):
   ```
   F=/root/.claude/projects/-home-user-blogspot/<세션UUID>/subagents/agent-<agentId>.jsonl
   ls -la "$F"        # mtime이 계속 갱신되면 아직 작업 중
   wc -l "$F"         # 이벤트 수가 늘고 있으면 살아 있음
   ```
   　 mtime이 5분 이상 멈췄고 마지막 assistant 이벤트의 `stop_reason`이 `end_turn`이면 **끝난 것**이다.
   　 그 마지막 메시지의 text 블록만 python으로 파싱해 결과를 꺼내 쓴다(전날 실제로 그렇게 살려냈다).
2. **Make 도구 프리픽스가 MCP 재연결마다 바뀐다.** 같은 세션 안에서 실제로 바뀌는 걸 확인했다 —
   처음엔 `mcp__dd5a2de6-0438-43ff-b141-005d5c400e62__*`(UUID)로 붙었다가,
   서버가 재연결된 뒤엔 `mcp__Make__*`로 붙었다. 둘 다 같은 시나리오 6177668을 정상 조회한다.
   → **어느 쪽도 정답으로 외우지 마라.** 이름을 쓰기 전에 매번 **`ToolSearch`에
   `scenarios_run` `data-store-records_list` 같은 기능어로 검색**해 그 시점의 실제 이름을 찾아 쓴다.
   `select:` 로 이름을 찍어 넣었다가 `No matching deferred tools found`가 나오면
   **Make가 죽은 게 아니라 프리픽스가 바뀐 것이다** — 기능어 검색으로 다시 찾으면 된다.
3. **예약 세션(`create_new_session_on_fire`)은 저장소도 MCP도 안 붙는다.**
   → 이 파이프라인을 **새 세션 방식으로 옮기지 마라.** 상주 세션 전용이다.
   (GlowShot이 이걸 몰라 7연속 실패했다 — `SMOKE-2026-09-09.md`)

## 1. 오늘 몫이 남았는지

`.claude/auto/RUNLOG.md`를 읽는다.
- 오늘(KST) 기록이 **3건이면 아무것도 하지 않고 종료**한다.
- 직전 실행이 원고를 커밋하지 못하고 끝났으면 **새 주제를 시작하지 말고 그것부터 끝낸다.**

## 2. 주제 선택 — `.claude/travel-calendar/calendar.tsv`

```
상태 = 미발행
AND 발행권장이 오늘부터 3주 이내
AND 경쟁률 < 5
AND 뚜벅이 ≠ 불가
정렬: 발행권장 임박 순 → 월검색량 큰 순
```
- `.claude/blog-topic-pipeline.md`의 **"이미 발행(중복 금지)"** 목록과 반드시 대조한다.
- 조건을 만족하는 게 **없으면** 글을 쓰지 말고 **키워드 실측만** 하고 종료
  (`.claude/keyword-tool.md`, Make 6031917 → 6032112). 캘린더에 새 지역을 채운다.

## 3. 취재 — `travel-journalist` **포그라운드**

프롬프트에 반드시 넣을 것:
- **뚜벅이 가능 판정을 가장 먼저** (불가면 그 주제를 접고 캘린더 `뚜벅이=불가`로 갱신)
- **폐장 / 매표마감 / 입장마감 / 탈것 운행종료 — 네 값을 각각 다른 출처 문장에서 따로**
- 출발지를 서울로 고정하지 말 것. 목적지 근거리 대도시 병기
- 모든 숫자에 **등급(A=공식 직접열람 / B=교차2건 / C=2차 / D=추정)**
- ★**C등급으로 시각·요금·버스번호를 단정하지 말 것**
- 마지막 1구간(정류장→목적지, 하차 후 도보 포함)은 **"운영자 네이버지도 확인 필요"**로 표시

## 4. 공식값 보강 — `.claude/web-tool.md`

기자가 C등급으로 남긴 **요금·운영시간·마감시각**을 지자체 공식 페이지에서 A등급으로 올린다.
연천에서 시티투어 시간표·요금·버스 배차를 전부 이 경로로 뚫었다.
★기자 값과 다르면 **공식값을 쓴다.** (연천 재인폭포 요금이 실제로 달랐다)

`naver-senior-travel-blogger` **포그라운드** 호출. `CLAUDE.md` 본문 규칙 전부 적용.

## 6. 평가 — `reader-panel-evaluator` **포그라운드**, 최대 4라운드

- **130 이상 AND 치명결함 0** → `상태: 통과`
- 4라운드에도 미달 → ★**가짜 통과 금지.** `상태: 미달(최고점 N)`으로 정직히 적고 **그대로 커밋**한다.
- ★**평가단 지적도 근거를 확인하고 반영한다.** 틀린 지적이 실제로 나온다
  (연천에서 "전곡역에서 걸어가긴 멀다"는 제안이 사실과 반대였다).
