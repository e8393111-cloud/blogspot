# witchbloom 블로그 글 생성 절차 (상태기계)

루트 `CLAUDE.md`의 모든 규칙을 따른다. 이 스킬은 그 규칙을 '순서'로 실행하는 절차다.
각 단계의 **종료조건**을 못 채우면 다음 단계로 넘어가지 않는다. 판단을 규칙으로 대체한다.

## STATE 1 — 팩트체크 (`travel-journalist` 실제 호출)
입력: 주제(지역/장소).
지시할 것:
- 교통: 기차/버스 시간표·요금·소요, **★귀경 막차**(당일치기 생명선). ★**출발지를 서울로 고정 금지** — 목적지 터미널·역을 축으로 서울+**근거리 대도시**(충청·영남·호남·수도권 등)를 함께, 귀경 막차도 방면별.
- 현지 이동: 시내버스/셔틀/시티투어 번호·배차·막차·하차 방향·도보 난이도, 택시 플랜B(대략 요금)
- 운영/요금(경로 65세+ 할인 포함)·무장애·응급 병원
- **★최신·신규 정보** 능동 탐색(연도 붙여 검색)
- 맛집: 상호·대표메뉴·가격·도보권·영업시간
- **공식/예매 URL**(버튼링크용, 실제 URL만)
원칙: '확인 권장'으로 떠넘기지 말고 대체 출처로 **실제 값**을 확보. 못 구한 건 이유 명시.
**종료조건**: 귀경 막차 + 현지 이동 수단 + 요금/운영 + 맛집 3곳 + 공식 URL ≥2 확보. 부족하면 재호출.

## STATE 2 — 집필 (정리형)
- **제목 3안 + 검색어 메모**: 지역+당일치기+코스 앞, '뚜벅이' 앞 금지, ≤35자, 확인된 숫자만.
- **본문 순서**: 검색기준📅 → 첫5줄(가능·교통·막차·플랜B) → 3초요약 박스 → (질문형 소제목) 교통·동선(STEP)·운영/요금·시니어 편의/무장애·볼거리·맛집 → 방문 전 체크 박스 → 전화 박스 → 한 줄 정리 → CTA → 해시태그 10.
- **레이아웃(정리형)**: 짧은 줄 + `✅ 라벨 : 값`/번호형. 3~5문장 줄글 덩어리 금지. 박스 3~5개. 사진 삽입 포인트를 본문 곳곳.
- **링크**: 예매·운영 `[버튼링크:이름|실제URL]`을 관련 문단 바로 밑. 지도=네이버지도. 말투=다정 ~해요체. 면책·☎는 박스로.
- **정보 풍부 + 체류시간**: 정리하되 실속 정보(메뉴·가격·시간표·팁)는 더 넉넉히.
**종료조건**: `CLAUDE.md` **'발행 전 자기점검'** 항목별 YES/NO를 출력해 전부 YES.

## STATE 3 — 평가 (`reader-panel-evaluator` 실제 호출, 본문 전문 전달)
5연령(30·40·50·60·70대) × 6항목(클릭·완독·이해·혼자따라가기·신뢰·유용/저장) × 5 = 150.
치명결함 0 여부 명시. 우선 패치 2~3개.

## STATE 4 — patch & 재평가 루프
총점<100 또는 치명결함>0 → 지적 반영해 STATE 2로. **최대 4라운드.**
- 검증 안 된 숫자는 평가단이 원해도 지어내지 않는다(대체 출처 or 범위+☎).
- 4라운드에도 미달이면 남은 결함을 사용자에게 보고하고 중단.
**종료조건**: 총점 ≥100 AND 치명결함 0.

## STATE 5 — 전달
- **영역1**(본문)과 **영역2**(이미지)를 각각 복붙용 코드블록으로.
- 영역2: 카드별 `비율 / 삽입 위치 / 카드 텍스트 / 영문 프롬프트`. 영역1 삽입점과 개수·이름 1:1. 배경=실제 사진 크롤링 기반, 세트색 1개(사진에서), 썸네일=표지, 맛집 카드 포함, CTA 16:9. 영문 꼬리표는 이미지 지침 원문 그대로.
- 말미에 통과 점수(◯/150·치명0)와 '실제 값' vs '당일 확인만 남긴 것'을 1~2줄 요약.

## 며칠 뒤 재발행 시
STATE 1을 **'최신 대조'**로 실행: 이전 값이 아직 맞는지 항목별(변동 없음 / 변경(새 값) / 미확인) + 신규 소식. **바뀐 것만** patch하고, 시점 영향(계절 운영·휴장 등)도 반영.

## 카드뉴스 요청 시
표지→공감→핵심 3~7→한눈 요약→CTA(블로그 유입) 8~12장. 카드당 메시지 1개·큰 글자. 숫자는 본문과 1:1. 세트색 1개·실제 사진 기반·워터마크. 마지막 카드는 "전체 코스·예매는 블로그에서"로 유입.
